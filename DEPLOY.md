# Streamlit Cloud: запуск демо

Застосунок запускається без ключів і показує позначений демонстраційний звіт про вигаданий профіль. Для реальних запусків налаштуй Secrets; вони не входять у Git-репозиторій.

## Деплой

1. Відкрий https://share.streamlit.io/ і вибери **Create app → Yup, I have an app**.
2. Вибери GitHub-репозиторій, гілку **main** і файл **streamlit_app.py**.
3. У **Advanced settings** вибери **Python 3.12**. Залежності також сумісні з локальним Python 3.14, на якому проведено перевірки.
4. Для живих запусків встав у **Secrets** конфігурацію з локального `.streamlit/secrets.toml`. Якщо такого файла ще немає, використай `.streamlit/secrets.toml.example` та заповни значення.
5. Натисни **Deploy**. `requirements.txt` встановить Python-пакети, а `packages.txt` — Chromium і FFmpeg.
6. У **Settings → Sharing** зроби застосунок публічним, щоб пересилати його URL. Репозиторій може залишатися приватним.

Офіційні інструкції: [Deploy](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy), [Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management), [Sharing](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app).

## Live-запуски

Потрібні `IG_USERNAME`, `IG_SESSIONID`, `IG_CSRFTOKEN`, `IG_DS_USER_ID`, `OPENCODE_API_KEY` і `APP_PASSWORD` (від 12 символів). Cookies відповідають Instagram-акаунту, через який відкривається цільовий профіль. Цільовий профіль може бути іншим.

Передай знайомим URL і код `APP_PASSWORD`. Публічний демонстраційний звіт відкривається без коду. Налаштування не виводять значення cookies та ключів у браузер. Під час реального запуску користувач підтверджує передачу матеріалів Contributor-моделі, яка може використовувати їх для навчання.

Одночасно виконується один реальний аналіз, у черзі може бути до чотирьох. Типовий денний ліміт — 10 запусків на весь застосунок (`APP_MAX_RUNS_PER_DAY`). Для маленького хостингу налаштовано два завантажувачі та чотири паралельні запити до моделі. Сховище обмежено приблизно 1 ГБ на нові запуски; поточний запуск може трохи перевищити межу.

Історія відокремлена за браузерними сесіями. Перезавантаження сторінки зі створенням нової Streamlit-сесії або перезапуск сервера може зробити історію недоступною. Тимчасові експорти й лічильник денних запусків зберігаються на диску інстансу; після скидання хостингом цього диска вони зникають. Звіти слід завантажувати одразу. Для стабільного довготривалого сервісу потрібні постійне сховище та збереження бюджетів поза інстансом.

Instagram може відхилити cloud-IP або вимагати оновлення сеансу навіть із cookies, які працюють локально. Таку поведінку можна перевірити лише на розгорнутому хостингу. Перезапуск після помилки аналізу використовує checkpoint і не надсилає успішно проаналізовані дописи повторно.

Вартість API визначається з фактичних даних usage. `model_usage` уже містить фінальний синтез; його вартість повторно не додається. Повний час вебзапуску включає скрап, завантаження, перетворення медіа, аналіз і синтез. Ціна API та час не є фіксованою обіцянкою на кожний профіль.

## Локальний запуск

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m streamlit run streamlit_app.py
```

Локально credentials беруться з `.env`, змінних процесу та `.streamlit/secrets.toml` у такому порядку пріоритету. Реальний `.streamlit/secrets.toml`, `.env`, `.runtime/` та `exports/` виключені з Git.

## Перевірки

```powershell
python -m unittest discover -s tests -v
```

Тести перевіряють навігацію й завантаження демо-звіту, ізоляцію результатів різних сесій, обмеження доступу до файлів, запуск offline-версії конвеєра, правильний підрахунок вартості, паралельність і повторення тимчасових помилок. Вони не роблять запитів до Instagram або платного API. Додатково локальний інтерфейс переглянуто у Chromium на desktop і mobile.
